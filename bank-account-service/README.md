# Bank Account Service

Small Spring Boot microservice for creating and managing bank accounts.

The service exposes the same account operations through both REST and GraphQL.
It uses an in-memory H2 database, so data is lost when the application stops.

## Technology stack

- Java 21
- Spring Boot 4.1.1
- Spring MVC for REST endpoints
- Spring GraphQL for GraphQL queries and mutations
- Spring Data JPA and Hibernate for persistence
- H2 for the runtime database
- MapStruct 1.6.3 for DTO/entity mapping
- Lombok for getters, setters, builders, and constructors
- Maven Wrapper for build and run commands
- Springdoc OpenAPI for REST API documentation

## Architecture

The project is a single backend service with a simple layered design:

```text
REST / GraphQL controllers
            |
        service layer
            |
      MapStruct mapper
            |
   Spring Data JPA repository
            |
        H2 database
```

- **Controllers** receive REST or GraphQL requests.
- **Service** contains account operations and not-found checks.
- **Mapper** converts request/response DTOs and the `BankAccount` entity.
- **Repository** provides CRUD access through `JpaRepository`.
- **Entity** represents the `BankAccount` table managed by JPA.
- **Exception handlers** convert REST and GraphQL failures into API errors.

## Main data model

`BankAccount` contains:

- `id`: UUID string generated by the service
- `createdAt`: creation date
- `balance`: account balance
- `currency`: currency code such as `MAD`
- `type`: `CURRENT_ACCOUNT` or `SAVING_ACCOUNT`

The application creates ten sample current accounts at startup through a
`CommandLineRunner`.

## REST API

Base path: `/api/bank-account`

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/bank-account` | List all accounts |
| GET | `/api/bank-account/{id}` | Get one account |
| POST | `/api/bank-account` | Create an account |
| PUT | `/api/bank-account/{id}` | Update an account |
| DELETE | `/api/bank-account/{id}` | Delete an account |

Example request:

```json
{
  "balance": 1500.0,
  "currency": "MAD",
  "type": "CURRENT_ACCOUNT"
}
```

REST resource-not-found errors return HTTP `404`. Unexpected errors return
HTTP `500` with a small JSON error object containing a message, status, and
timestamp.

## GraphQL API

GraphQL endpoint: `/graphql`

GraphiQL is enabled for local exploration. The schema is in
`src/main/resources/graphql/schema.graphqls`.

Available operations:

- `accountList`
- `bankAccountById(id)`
- `addBankAccount(bankAccount)`
- `updateBankAccount(bankAccount, id)`
- `deleteBankAcount(id)`

## Configuration and local run

The default configuration is in `src/main/resources/application.yaml`:

- HTTP port: `8082`
- H2 JDBC URL: `jdbc:h2:mem:account-db`
- H2 console: enabled
- JPA schema mode: `update`
- SQL logging and formatted SQL: enabled
- GraphiQL: enabled

Run the service from the `bank-account-service` directory:

```bash
./mvnw spring-boot:run
```

On Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

The packaged application can be built with:

```powershell
.\mvnw.cmd clean verify
```

Useful local URLs:

- REST API: `http://localhost:8082/api/bank-account`
- GraphiQL: `http://localhost:8082/graphiql`
- H2 console: `http://localhost:8082/h2-console`
- OpenAPI UI: `http://localhost:8082/swagger-ui.html`

For the H2 console, use JDBC URL `jdbc:h2:mem:account-db`, user `sa`, and an
empty password.

## Development notes

- DTOs keep API models separate from the JPA entity.
- Constructor injection is used for controller and service dependencies.
- MapStruct keeps mapping code generated and consistent.
- `RessourceNotFoundException` centralizes missing-account behavior.
- The current H2 setup is suitable for demos and local development, not
  durable production storage.
- The current test verifies that the Spring application context starts.
